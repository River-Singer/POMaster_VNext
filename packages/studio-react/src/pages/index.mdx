# React · Geist 抽屉

React 栈的前端规范和组件都在这里。项目选 React 时，界面按 Vercel Geist 设计，组件用 **shadcn/ui**，
样式用 **Tailwind CSS 4**，图标用 **lucide-react**（项目决策 D-S9，见 `docs/design-standard.md`）。
Vue 栈对应的是另一个抽屉「Vue · Ant Design」。两个抽屉的规范目录相同（统一骨架
`packages/cli/seeds/design-standards/skeleton.yaml`），但条文、示例、组件和工程做法都按各自的技术栈写。

## 侧栏里有什么

- **规范**：React 栈开发必须遵守的前端规范。分基础（色彩、字体、标题层级、图标、材质、布局、栅格、间距、
  动效）、组件、设计模式（全局规则、原则、模板文档、体验管理、数据呈现）和工程规范（前端架构、状态管理、性能、
  安全、会话与凭据、报错、保护页、页面加载、缓存、异步等）。每条规则有编号、数值与出处、执行方式（机器门禁 /
  人工评审）和实时渲染的「这样做 / 别这样做」。页面由 `packages/cli/seeds/design-standards/geist.yaml` 生成，
  AI 读同源的孪生 `packages/studio-react/twin/design-standard.geist.json`（或
  `pomaster design show --system geist --json`）。
- **Geist 组件**：项目里每个 shadcn 组件一页（`src/components/ui/` 下的源码），展示变体、尺寸和状态，
  带实验场的可以直接调属性。组件源码进项目、由项目维护，这是 shadcn/ui 的用法：不装组件包，组件文件就是项目代码。
- **Foundations / Geist（说明）**：组件和主题从哪来、哪些是近似。

## 组件与 Radix

选择器、多选、单选、标签页、下拉菜单、对话框、气泡卡片、文字提示、进度条、开关、分隔线建在 Radix
（`radix-ui`）之上：焦点管理、键盘操作、读屏语义由 Radix 负责，组件只管样子。按钮在 Radix 的 `asChild`
里当触发元素时会收到 ref，所以 `Button` 用 `forwardRef` 写（项目用 React 18）。

## 改规范、看效果

- 改规范只改规范源：`pomaster design validate --system geist` 校验，`node packages/studio-react/run.mjs generate`
  重新生成规范页和 AI 孪生。项目里落地后的规范用 `pomaster design adopt` / `design set` / `update spec` 维护，
  设置 `POMASTER_STUDIO_PROJECT=<项目目录>` 后规范页从项目规范生成。
- 组件页是手写的 `src/gallery/*.stories.tsx`：新增或改动 `src/components/ui/` 下的组件时同步改对应的页，
  `packages/studio-react/tests/gallery.spec.ts` 会检查每个组件都有页。
- 只看这个抽屉：`corepack pnpm studio:react:dev`（端口 6007）；两个抽屉一起看：`corepack pnpm studio:dev`。
