# POMaster 组件可视化画廊（总览）

本 Storybook（`packages/studio`，总 Storybook 里的「Vue · Ant Design」抽屉）分两部分：

- **规范**（侧栏最上方「规范」分区）：开发必须遵守的前端设计规范（Ant Design 预设）——基础（色彩、字体、
  标题层级、图标、材质、布局、栅格、间距、动效）、组件、设计模式、工程规范。每条规则带编号、演示与对照表、
  数值与出处、执行方式（机器门禁 / 人工评审）和实时渲染的「这样做 / 别这样做」；状态管理带可操作的实验。
  目录与 React · Geist 抽屉相同（统一骨架 `packages/cli/seeds/design-standards/skeleton.yaml`），还没写的页
  标「待补」。页面由 `packages/cli/seeds/design-standards/antd.yaml` 生成，AI 读同源的孪生
  `packages/studio/twin/design-standard.json`（或 `pomaster design show --json`），两边盖同一个规范指纹。
  改规范只改那份源：`pomaster design validate` 校验，`node packages/studio/run.mjs generate` 重新生成。
- **画廊**（其余分区）：组件、原型、Overlay 等的参照呈现。

> 画廊部分是参照呈现，权威语义以 catalog / seeds 锚定源为准；全部生成页由生成器从既有物料
> 只读渲染，不预置任何业务实体或业务组件。

## 组件类型取并集

统一骨架的 97 个组件领域在本画廊都有组件页（与 React · Geist 抽屉对称）：ant-design-vue 有的落到
「AntDV 组件/<族>」页，页说明里写「对应规范组件领域」（如 Dropdown 页对应分裂按钮、下拉菜单、右键菜单）；
ant-design-vue 没有的 16 个类型——代码块、命令片段、滚动区、命令面板、选择卡片、地址输入、破坏性确认输入、
筛选条、反馈收集、主题切换、视频、相对时间、JSON 查看器、中间省略、设备外框、书封——按 antd 的 token
（`theme.useToken()`：色、圆角、字号、间距、投影）自建在 `src/components/`，交互件尽量用 antdv 的组件拼，
页在「AntDV 组件/自建」。映射表是 `scripts/lib/component-areas.mjs`，`tests/component-areas.spec.ts` 核对。

## 交互态矩阵（S1）与语义映射层（S4）

- **交互态矩阵**：高频组件族在默认形态之外提供 disabled / loading / size / 变体组合
  （type/shape/danger 等）交互态 stories——prop 词形全部为 antdv 4.2.6 官方 API，
  逐态真实挂载断言；无交互态的族与服务式 API 显式缺席（不凑数）。
- **archetype↔组件映射层**：每张语义卡有「建议组件组合」节（逐条溯源到语义字段与
  主题文档），组件 story 反向注记「服务场景」——配置在
  `packages/studio/scripts/lib/archetype-component-map.json`（画廊策展配置，非 catalog 物料）。

## Database Struct（S5 占位分区）

画廊起步没有业务数据结构——「Database Struct」分区是刻意的占位：随项目数据结构
定义后填充，业务实体走 New Entity Gate（G-D 边界不预置）；分区页呈现「该写什么」
规范指引（data-and-transactions 主题 MUST/Checklist 透传）与 baseline data 面导航。

## React · Geist 抽屉

`packages/studio-react` 是另一个 Storybook 实例（`@storybook/react-vite`），放 React 栈的前端规范
（Vercel Geist 预设，`packages/cli/seeds/design-standards/geist.yaml`）和项目里的 shadcn/ui 组件页。
两个抽屉目录相同，条文、示例、组件和工程做法按各自技术栈写：本画廊是 Vue 3 + ant-design-vue，
那边是 React + shadcn/ui + Tailwind CSS 4。

```bash
corepack pnpm studio:dev          # 两个抽屉一起（总 Storybook）
corepack pnpm studio:vue:dev      # 只起本画廊（端口 6006）
corepack pnpm studio:react:dev    # 只起 React · Geist（端口 6007）
```

## 生成器纪律

- MDX/stories 全部由 `packages/studio/scripts/lib/*.mjs` 程序化生成（幂等、可重放）；
  `generated/` 不入 git——入库的是生成器 + 配置 + 本类少量手写页。
- 重新生成：`corepack pnpm studio:dev` / `studio:build` 前自动重建；也可单独
  `node packages/studio/run.mjs generate`。
- 覆盖/幂等由 `packages/studio/tests/generators.spec.ts` 钉住（41/71/18/4/1 计数 +
  178 stories 分母 + 双跑 diff 空）；design tokens 页另有
  `packages/studio/tests/design-tokens-page.spec.ts` 逐值钉（期望全部从 seed 装载派生——
  44 真值 + 14 UNKNOWN 占位 + seed 改页随）。

## 技术形态边界

- archetype 是语义构件非可渲染组件——画廊以 MDX 语义卡呈现（Storybook MDX 实现
  是 React-only，Vue 实体只出现在 story 侧）。
- Geist 是 React 设计系统，没有 Vue 组件库本体：本画廊不放 Geist 内容，Geist 的规范与组件都在 React · Geist 抽屉。
- 业务组件/业务实体零出现；发现疑似业务面内容请按宪法 §32 冲突报告通路上报，不静默。
